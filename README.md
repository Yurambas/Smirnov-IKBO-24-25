# depgraph — визуализация графа зависимостей Cargo

## Общее описание

Консольная программа на Java (JDK 17+, без внешних библиотек). Получает прямые зависимости
пакета Rust (формат Cargo), строит граф с учётом транзитивности обходом в ширину (BFS, без
рекурсии), выводит порядок загрузки и рисует граф в формате Graphviz / SVG.

Источники данных:

* `real` — разреженный индекс Cargo (например, `https://index.crates.io`). Берётся последняя
  не отозванная версия пакета, учитываются только обычные (`normal`), не опциональные и не
  платформенные зависимости.
* `test` — текстовый файл тестового репозитория, пакеты названы большими латинскими буквами.

## Параметры командной строки

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `--package` | имя анализируемого пакета (обязательно) | — |
| `--repo` | URL индекса (режим `real`) или путь к файлу (режим `test`), обязательно | — |
| `--mode` | `real` или `test` | `real` |
| `--output` | имя файла изображения, расширение `.svg` | `graph.svg` |
| `--max-depth` | максимальная глубина анализа, целое >= 0 (корень — глубина 0) | `3` |
| `--filter` | пакеты, в имени которых есть подстрока, не учитываются | нет |
| `--show-params` | вывести все параметры в формате ключ-значение | выкл. |
| `--direct` | вывести только прямые зависимости пакета | выкл. |
| `--load-order` | вывести порядок загрузки зависимостей | выкл. |

`--direct` и `--load-order` вместе не используются. Без них программа печатает DOT-описание
графа и сохраняет `.svg` (и рядом `.dot` с тем же именем). Для SVG нужен установленный
Graphviz (команда `dot`).

## Формат тестового репозитория

Строка `A: B C` означает «A зависит от B и C». Пустой список допустим (`D:`), `#` начинает
комментарий. Примеры: `examples/test_repo.txt` (есть цикл A → C → E → A),
`examples/tree.txt`.

## Сборка и тесты

```
make build   # компиляция в build/main
make test    # компиляция и запуск тестов из tests/
make run ARGS="--package A --repo examples/test_repo.txt --mode test --max-depth 3"
make clean
```

## Примеры

Параметры и прямые зависимости (этапы 1 и 2):

```
make run ARGS="--package A --repo examples/test_repo.txt --mode test --show-params --direct"
make run ARGS="--package serde --repo https://index.crates.io --direct"
```

Граф с глубиной и фильтром, циклы обрабатываются (этап 3):

```
make run ARGS="--package A --repo examples/test_repo.txt --mode test --max-depth 2"
make run ARGS="--package A --repo examples/test_repo.txt --mode test --max-depth 5 --filter D"
```

Порядок загрузки (этап 4) — зависимости идут раньше зависимых, обратные рёбра циклов
игнорируются:

```
make run ARGS="--package A --repo examples/test_repo.txt --mode test --load-order"
```

Визуализация (этап 5), готовые результаты лежат в `examples/graph_*.svg`:

```
make run ARGS="--package A --repo examples/test_repo.txt --mode test --output graph.svg"
make run ARGS="--package tokio --repo https://index.crates.io --max-depth 2 --output tokio.svg"
```

## Сравнение с Cargo (заполнить после запуска на своей машине)

Для сравнения порядка загрузки используйте `cargo tree -p <пакет>`, для графа —
`cargo tree` / `cargo depgraph | dot -Tsvg`. Возможные причины расхождений: Cargo учитывает
выбранные версии и features (здесь берётся последняя версия и только обязательные
зависимости), dev- и build-зависимости, платформенные зависимости; порядок сборки в Cargo не
единственный — допустим любой топологический порядок, а сборка идёт параллельно.
